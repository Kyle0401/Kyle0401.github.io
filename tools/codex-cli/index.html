Codex CLI 启动命令

记录当前 Windows PowerShell 环境下启动 Codex CLI 的固定命令。使用自定义 CODEX_HOME，并通过指定的 codex.cmd 启动。

PowerShell Codex CLI Windows 2026-09-28

1. 启动命令

打开 PowerShell 后依次执行：

$env:CODEX_HOME = 'F:\CodexCLIHome' & 'F:\nodeJS\node_global\codex.cmd' --no-daemon

第一行指定 Codex CLI 使用的主目录；第二行调用本机安装的 codex.cmd 并启动交互式 Codex CLI。

部分 含义
$env:CODEX_HOME 设置当前 PowerShell 会话中的环境变量，告诉 Codex 使用哪个目录保存和读取配置。
F:\CodexCLIHome 当前使用的 Codex 配置与数据目录。
& PowerShell 的调用运算符，用来执行后面的程序或脚本路径。
F:\nodeJS\node_global\codex.cmd 本机通过 Node.js 全局安装的 Codex CLI 启动脚本。
--no-daemon 以不使用后台 daemon 的方式启动 Codex CLI。
注意：$env:CODEX_HOME = ... 只对当前 PowerShell 会话生效。关闭当前终端后重新打开 PowerShell，需要再次执行这一行，除非以后把它设置成持久环境变量。

2. 检查 Codex CLI 版本

& 'F:\nodeJS\node_global\codex.cmd' --version

3. 检查登录状态

& 'F:\nodeJS\node_global\codex.cmd' login status

如果当前主要通过自定义 API Provider 使用 Codex CLI，显示 Not logged in 并不一定意味着模型 API 无法使用；ChatGPT 登录状态与自定义 API Provider 的认证是两回事。

4. 自定义 API 与 ChatGPT 登录可以同时存在

当前 Codex CLI 使用的是自定义模型 Provider（例如 codex_team），模型请求通过对应的 API Key 进行认证。这和 Codex CLI 的 ChatGPT 登录状态是两套不同的认证链路。

自定义 API Key → 模型请求 ChatGPT 登录 → ChatGPT 身份 / 远程插件与连接器能力

因此，即使模型仍然走自定义 API，也可以额外登录 ChatGPT。这样不需要放弃现有的 API Provider。

$env:CODEX_HOME = 'F:\CodexCLIHome' & 'F:\nodeJS\node_global\codex.cmd' login

login 会启动 Codex CLI 的 ChatGPT 登录流程。登录完成后，可以再次检查状态：

& 'F:\nodeJS\node_global\codex.cmd' login status

如果登录成功，通常会显示已经通过 ChatGPT 登录。此时模型仍然可以继续使用 model_provider = "codex_team" 指定的自定义 Provider；ChatGPT 登录不会自动把模型切回 OpenAI 官方 Provider。

为什么需要额外登录 ChatGPT？
仅使用自定义 API 时，Codex CLI 可能拿不到需要 ChatGPT 身份认证的远程插件目录，例如 GitHub 等连接器。额外登录 ChatGPT 后，可以再通过 /plugins 或 plugin list --available 检查这些插件是否对当前账号下发。是否实际出现仍取决于当前账号和远程插件目录。

可以使用下面的 PowerShell 命令检查当前可用插件中是否存在 GitHub：

$data = & 'F:\nodeJS\node_global\codex.cmd' plugin list --available --json | ConvertFrom-Json $data.available | Where-Object { $_.name -eq 'github' } | Format-List *

如果有结果，说明 GitHub 插件已经出现在当前可用目录中；如果没有输出，则当前目录中仍没有 GitHub。

不要混淆：自定义 Provider 配置中的 requires_openai_auth = false 是给该模型 Provider 使用的，不要为了登录 ChatGPT 或启用插件而直接改成 true。模型 API 认证和 ChatGPT 登录是两个不同问题。

5. 记忆版

以后忘记怎么启动时，只需要记住两步：

# 1. 指定 Codex Home $env:CODEX_HOME = 'F:\CodexCLIHome' # 2. 启动 Codex CLI & 'F:\nodeJS\node_global\codex.cmd' --no-daemon
